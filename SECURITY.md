# Security Policy

## Supported versions

Security fixes are applied to the latest development version until the first stable release policy is published.

## Reporting a vulnerability

Do not report suspected vulnerabilities in a public GitHub issue.

Use GitHub's private vulnerability reporting feature for this repository. If it is unavailable, contact the maintainer through the public GitHub profile and include a minimal reproduction, affected version or commit, impact, and suggested mitigation if known.

Do not include credentials, cookies, access tokens, copyrighted media, or sensitive personal data in a report. The maintainer will coordinate a fix before public disclosure where appropriate.

## Scope

Relevant areas include external process invocation, untrusted URL and file-path handling, bundled tools, output-path traversal, dependency updates, and release artifacts.
